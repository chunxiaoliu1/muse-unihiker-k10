# K10 feature map

Feature logic lives in dedicated directories. The board adapter supplies hardware resources; shared Muse code calls feature interfaces.

| Feature | Entry point | Where to make changes |
|---|---|---|
| SDK Token and USB setup | `usb/`, `../../main/credentials/`, `../../tools/muse/usb-config/` | USB resource lifecycle, menu entry, NVS and boot cache, serial protocol and static page; public overlay: `sdkconfig.muse-k10-public` |
| Temperature, humidity, light, acceleration | `sensors/` | Sampling and thresholds in `sensor_config.h`; drivers in `drivers/`; channel registration in `k10_catalog.c` |
| Sensor events | `sensors/events/` | Scheduling and messages in `sensor_events.c`; humidity policy in `k10_humidity_policy.h`; asynchronous delivery in `muse_event_sender.c` |
| On-demand camera | `camera/` | Capture options in `k10_camera_config.h`; acquisition and JPEG encoding in `drivers/gc2145.c`; result format, command description and captions in `k10_camera.c` |
| Online speech synthesis | `tts/`, `../../main/credentials/tts_credentials.c` | Cartesia PCM WebSocket, prebuffering, cancellation, USB/NVS settings for the user's key, voice and language |
| K10 hardware adapter | `boards/board_dfrobot_unihiker_k10.c` | Display, A/B buttons, RGB LEDs, microphone, speaker, shared I2C and XL9535 |
| Build and diagnostics | `../../tools/muse/` | `k10-public.ps1` for public builds; `k10.ps1` for development; `camera.py` and `sensors.py` for diagnostics |

The board adapter owns pins, initialization, hardware access and shared locks. The camera receives only a reset callback; sensors receive the existing I2C bus. Features must not recreate or overwrite shared board resources. Display, buttons, LEDs and audio currently share the board adapter; split them into drivers if they grow substantially.

## Shared-code boundaries

- `main/noise_control.cpp` registers Muse commands; sensor and camera descriptions come from their feature modules.
- `main/app.c` dispatches `sensors.read`, starts asynchronous `camera.capture`, and sends results. Request IDs and session generations belong to the protocol layer.
- `muse_input.c` forwards serial diagnostics to feature modules.
- `muse_menu.c` displays text generated by the sensor module.
- `muse_chat_session.cpp` forwards replies to TTS and owns cancellation generations, PCM playback handoff, captions and text fallback.
- `Kconfig` and `CMakeLists.txt` select features and sources. Disabling the K10 camera excludes its driver.

K10 reuses the existing BLE pairing, Wi-Fi, Muse protocol, voice-upload, font and MP3 frameworks. Cartesia is enabled through a K10-specific option; other boards retain the disabled implementation.
